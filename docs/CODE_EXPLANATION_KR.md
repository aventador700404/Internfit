# InternFit 코드 설명 및 AI 활용 기록

작성일: 2026-11-01  
코드 확인 기준: `b97f00ecfa3a045dd4becda1f2ba4f2ad7f26d82`

## 1. 프로젝트 목적과 주요 기능

InternFit은 이력서와 채용공고를 비교해 지원 우선순위를 검토하는 웹서비스다. 사용자가 이력서 파일과 공고 URL 또는 본문을 제출하면 적합도 점수, 등급, 필수요건 관련 경고, 경험의 근거와 보완 방향을 제공한다. 점수는 서비스 내부 평가 기준에 따른 참고값이다.

이력서와 공고의 표현이 달라도 관련 경험을 파악하도록 LLM을 선택적으로 사용한다. 최종 점수는 Python의 평가 규칙으로 계산하며, 필수 언어·학위 조건과 감점·상한도 Python에서 처리한다.

## 2. 사용자의 입력이 결과로 바뀌는 과정

1. **입력:** 웹 화면이 DOCX/PDF 파일과 공고 URL 또는 직접 붙여 넣은 본문을 `/api/analyze`로 보낸다.
2. **정보 추출:** 이력서에서 경험·언어·도구·학력 등의 정보를 추출하고, 공고에서 직무와 자격요건을 정리한다. 공고 페이지를 제대로 읽지 못하면 본문을 직접 붙여 넣도록 안내한다.
3. **선택적 의미 해석:** LLM이 경험과 요구사항의 의미를 정리하고, 일치 근거와 이력서 수정 제안을 작성한다. 서버는 인용 또는 참조한 원문 구간이 입력 자료에 존재하는지 확인한다. 이 검사는 출처 확인이며 해석의 정확성까지 보장하지는 않는다.
4. **점수 계산:** 같은 입력으로 규칙 기반 점수를 계산한다. 유효한 LLM 결과가 있으면 보완된 경험·요구사항 정보를 적용해 같은 Python 함수로 다시 계산한다.
5. **분석 기록:** 점수 구성, 필수요건, LLM 적용 여부와 실패 원인 등을 기록한다. 설정된 경우 Supabase에도 저장한다.
6. **결과 표시:** 브라우저가 점수와 경고, 일치 근거, 개선 방향을 표시한다.

## 3. 어디에서 무엇을 처리하는가

| 파일 | 담당 기능 |
|---|---|
| [internfit_web/index.html](../internfit_web/index.html) | 업로드, 공고 입력, 분석 요청, 결과 표시를 담당하는 HTML·CSS·JavaScript 화면 |
| [internfit_web/server.py](../internfit_web/server.py) | Python 표준 HTTP 서버. 파일·공고 입력을 받고 추출, LLM, 점수, 기록 처리를 연결 |
| [cv_parser.py](../internfit/core/cv_parser.py) | DOCX/PDF에서 이력서 텍스트를 추출하고 후보자 정보를 구성. PDF에는 텍스트 추출과 제한된 OCR 경로가 있음 |
| [job_parser.py](../internfit/core/job_parser.py) | 공개 공고 페이지 추출, 본문 품질 확인, 직접 입력된 공고 처리 |
| [scoring.py](../internfit/core/scoring.py) | 직무·자격·도구·도메인·경험 근거를 비교하고 점수, 감점, 상한, 필수요건 경고를 계산 |
| [llm_client.py](../internfit/core/llm_client.py) | LLM 요청 구성, 구조화된 응답 처리, 출처 검증, 오류 상태 분류 |
| [analysis_cache.py](../internfit/core/analysis_cache.py) | 같은 내용에 대한 성공한 LLM 결과를 제한된 시간 동안 재사용 |
| [llm_budget.py](../internfit/core/llm_budget.py) | 요청 전 LLM 예산 예약 및 사용 한도 관리 |
| [analysis_trace.py](../internfit/core/analysis_trace.py) | 규칙 기반·LLM 보조 결과를 비교하고 근거 및 검증 기록을 구성 |
| [telemetry.py](../internfit/core/telemetry.py), [telemetry_store.py](../internfit/core/telemetry_store.py) | 분석 이벤트 출력 및 선택적 Supabase 저장 |
| [Dockerfile](../Dockerfile), [render.yaml](../render.yaml) | Python과 PDF/OCR 실행 환경을 Docker로 묶고 Render 웹서비스로 실행하도록 설정 |

초기 Streamlit 화면은 [internfit/app.py](../internfit/app.py)에 남아 있다. 현재 웹 요청 흐름의 시작점은 `internfit_web/server.py`다.

## 4. LLM을 붙인 이유와 역할

규칙 기반 비교는 표현이 다르면 관련 경험을 놓치거나 일반적인 설명을 반복할 수 있다. LLM은 한국어·영어 표현의 의미를 정리하고, 직무와 연결되는 근거 및 구체적인 수정 방향을 제시하는 데 사용한다.

| 처리 | 구현 방식 |
|---|---|
| 경험·요구사항의 의미 정리, 필수/우대 신호 보조 분류 | LLM 의미 해석 결과를 서버에서 검증 후 사용 |
| 점수의 최종 산술 계산 | `assess_fit()`의 Python 규칙 |
| 필수 언어·학위 조건, 감점 및 점수 상한 | Python 평가 로직 |
| 이력서 수정 제안의 출처 확인 | 요청별 원문 구간 ID 또는 원문 인용 검증 |
| API 실패·예산 소진·유효하지 않은 응답 | 규칙 기반 결과로 처리하고 상태를 기록 |

LLM이 최종 숫자를 직접 반환하는 구조는 아니다. 다만 LLM이 보완한 경험·요구사항 정보가 평가 입력을 바꾸므로 최종 점수는 달라질 수 있다. 서버는 `rule_only_score`와 최종 점수를 함께 기록해 그 차이를 검토할 수 있게 한다.

동일한 입력과 모델·평가 버전에 대한 유효한 결과는 프로세스 내부에서 30분 동안 재사용한다. 재사용 여부와 실패 상태도 기록하며, 이력서·공고 파싱과 최종 점수 계산은 요청마다 수행한다.

## 5. DB에는 무엇을 남기는가

Supabase는 분석 결과 검토와 예산 관리에 사용한다.

- **`analysis_events`:** 점수와 구성 항목, 필수요건, 파싱 상태, 규칙 기반 대비 변화, LLM 사용·실패 상태, 버전 등 분석 이벤트.
- **선택적 근거 기록:** 사용자가 제출한 공유 설정과 고지 버전이 유효하면 제한된 원문 발췌와 설명을 같은 이벤트에 저장한다. 현재 화면의 공유 선택은 기본 체크 상태이며 사용자가 해제할 수 있다.
- **`llm_usage`:** LLM 예산 예약·사용 관리 기록.

업로드한 파일 원본과 문서 전체를 영구 저장하는 구조는 아니다. 제한된 발췌에는 개인정보가 남을 수 있으며, 공유 설정을 해제해도 AI 분석을 활성화한 경우 추출 텍스트는 LLM 요청에 사용된다. 저장 범위와 삭제 방법은 [telemetry.md](telemetry.md)에 설명돼 있다.

DB 설정이 없거나 저장에 실패해도 분석은 계속할 수 있다. 로그는 모델을 자동 학습시키는 자료가 아니라, 소유자가 사례별로 오류와 평가 기준을 검토하기 위한 기록이다.

## 6. 개발 과정에서의 AI 활용과 개발자 역할

개발 기록에 따르면 Codex와 Claude Code를 서비스 구현에 활용했다. 개발 과정의 AI 도구와 서비스 실행 중 호출하는 LLM API는 서로 다른 역할을 한다.

| 구분 | 역할 |
|---|---|
| 개발자 | 지원 직무 판단의 불편함 발견, 서비스 목적·기능 우선순위 결정, 평가 기준 요구사항 정리, 베타 결과에 대한 개선 요청 |
| AI 개발 도구 | 요구사항을 바탕으로 코드 초안과 수정안, 테스트 및 문서 작성 지원 |
| 실행 중 LLM API | 이력서·공고의 의미 해석과 설명·수정 제안 보조 |
| 이 문서 | 실제 저장소 파일과 기존 개발 문서를 대조해 처리 흐름과 확인 범위를 설명 |

개발 과정에서는 과도하게 높은 점수, 반복되는 설명, LLM 응답 실패 등을 개선 과제로 다뤘다. 현재 코드는 실패 원인을 단계별로 남기고 규칙 기반·LLM 보조 결과를 비교할 수 있도록 구성돼 있다. 이는 진단 기능의 구현이며, 모델 정확도가 개선됐다는 정량 성과와는 구분한다.

## 7. 실행·검토 방법과 현재 범위

저장소 루트에서 웹 화면을 실행하는 기본 명령은 다음과 같다.

```bash
python -m pip install -r internfit_web/requirements.txt
python internfit_web/server.py 8000
```

브라우저에서 `http://127.0.0.1:8000`을 연다. API 키가 없으면 규칙 기반으로 동작한다. 로컬 OCR에는 별도 Tesseract 실행 환경이 필요할 수 있으며, Dockerfile에는 한국어·영어 OCR 패키지가 포함돼 있다.

- **구현 확인:** 파일·공고 처리, 선택적 LLM, Python 평가, 진단 기록, Supabase 저장 경로, Docker/Render 설정.
- **테스트 코드:** [internfit/tests](../internfit/tests)에 파싱, 평가, 한국어, LLM, 캐시, 추적 기록 등에 대한 테스트가 있다.
- **추가 검토:** 다양한 이력서·공고에서의 점수 보정, LLM 해석의 타당성, 공고 사이트별 추출 및 실제 배포 환경의 동작.
- **이번 문서 작업:** 소스와 기존 문서를 읽어 설명을 작성했다. 테스트·배포·실제 API 호출을 새로 실행한 결과를 보고하는 문서는 아니다.

상세 변경 이력은 [CHANGELOG](../CHANGELOG.md), 설계 배경은 [decisions.md](decisions.md), LLM 세부 동작은 [llm.md](llm.md)를 참고한다.
